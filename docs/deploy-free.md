# Deploying MemOS for free (Render + Neon + Upstash + Cloudflare Pages)

No server to manage and no credit card needed. Each part runs on a different free service:

| Part | Service | Free plan (check current terms) |
|---|---|---|
| Backend (Spring Boot, Docker) | **Render** | 512 MB RAM, small CPU share, sleeps after 15 min without traffic |
| Postgres + pgvector | **Neon** | ~0.5 GB storage, suspends when idle, monthly compute-hour allowance |
| Redis (caches, rate limits) | **Upstash** | 256 MB, 500K commands/month |
| Frontend (React) | **Cloudflare Pages** | Static hosting, generous limits |

Trade-offs compared with a single server (`docs/deploy-oracle.md`): uploads are limited to
**10 MB**, the first request after the backend has slept takes up to a minute or two (prevented
by the keep-alive ping in step 6), and uploads waiting to be processed are lost if the backend
restarts (the document then asks you to upload the file again).

Use the **Singapore** region everywhere (closest to India); it keeps the services close together.

## 1. Neon (database)

1. Sign up at <https://neon.tech> (GitHub sign-in is easiest).
2. Create a project: name `memos`, Postgres **16 or 17**, region **AWS Asia Pacific (Singapore)**.
3. Open **Connect** (or *Connection details*). **Turn off "Connection pooling"**; the app needs
   the direct connection for migrations. Note:
   - **host**, e.g. `ep-cool-name-123456.ap-southeast-1.aws.neon.tech`
   - **database**, e.g. `neondb`
   - **user** and **password**
4. Your JDBC URL is:
   ```
   jdbc:postgresql://<host>/<database>?sslmode=require&reWriteBatchedInserts=true
   ```

The app creates its tables and enables pgvector itself on first start.

## 2. Upstash (Redis)

1. Sign up at <https://upstash.com>.
2. **Create database** → Redis → name `memos`, region **ap-southeast-1 (Singapore)**, TLS on.
3. From the database page note the **Endpoint** (host, e.g. `apt-cat-12345.upstash.io`), the
   **port** (`6379`) and the **password**.

## 3. Render (backend)

1. Sign up at <https://render.com> with GitHub and allow access to the `MemOS` repository.
2. **New → Blueprint** → choose the repository. Render reads `render.yaml` and asks for the
   secret values:

   | Variable | Value |
   |---|---|
   | `SPRING_DATASOURCE_URL` | the JDBC URL from step 1 |
   | `SPRING_DATASOURCE_USERNAME` / `_PASSWORD` | Neon user / password |
   | `REDIS_HOST` | Upstash endpoint (host only, no `https://` or port) |
   | `SPRING_DATA_REDIS_PASSWORD` | Upstash password |
   | `GEMINI_API_KEY` | from <https://aistudio.google.com/apikey> |
   | `MEMOS_CORS_ALLOWED_ORIGINS` | put `https://example.com` for now; updated in step 5 |
   | `MEMOS_INVITE_CODE` | a code you only share with people you want to use the app |

   `JWT_SECRET` is generated by Render automatically.
3. **Apply**. The first build takes about 10 minutes. When the service is live, open
   `https://<your-service>.onrender.com/actuator/health`; it should show `{"status":"UP"}`.
   Note this backend URL.

## 4. Cloudflare Pages (frontend)

1. Sign up at <https://dash.cloudflare.com> → **Workers & Pages** → **Create** → **Pages** →
   **Connect to Git** → choose the `MemOS` repository.
2. Build settings:

   | Setting | Value |
   |---|---|
   | Framework preset | Vite (or None) |
   | Root directory | `frontend` |
   | Build command | `npm run build` |
   | Build output directory | `dist` |

3. Environment variables (Production):

   | Variable | Value |
   |---|---|
   | `VITE_API_BASE_URL` | the Render backend URL from step 3, no trailing slash |
   | `VITE_MAX_UPLOAD_MB` | `10` |
   | `NODE_VERSION` | `22` |

4. **Save and Deploy**. Note the site URL, e.g. `https://memos-xyz.pages.dev`.

## 5. Connect frontend and backend

In Render → `memos-backend` → **Environment**, set `MEMOS_CORS_ALLOWED_ORIGINS` to the Cloudflare
Pages URL from step 4 (no trailing slash) and save; Render redeploys automatically.

Open the Pages URL, register with your invite code, upload a document and ask a question.

## 6. Keep the backend awake (optional, recommended)

Free Render services sleep after 15 minutes without traffic. A free uptime monitor stops that:

1. Sign up at <https://uptimerobot.com> (or <https://cron-job.org>).
2. Add an **HTTP(s)** monitor for `https://<your-service>.onrender.com/actuator/health`,
   every **5–10 minutes**.

One always-on service uses about 744 of Render's 750 free hours a month. The health check doesn't
touch the database or Redis, so these pings don't use Neon or Upstash quota.

## Updating

Push to `main`: Render rebuilds the backend (only when backend files change) and Cloudflare
Pages rebuilds the frontend. Database migrations run automatically on backend start.

## Limits to keep in mind

- **Gemini free tier:** about 5 chat requests/minute shared by everyone; follow-up rewriting is
  off by default here for that reason.
- **Neon storage:** roughly tens of thousands of document chunks; the per-user limits
  (`MEMOS_LIMIT_*`) keep any one account from filling it.
- **Upstash:** 500K commands/month. If exceeded, caching and rate limits stop working but the
  app keeps answering.
